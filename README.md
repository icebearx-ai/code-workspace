# Code Workspace

Code Workspace is a local multi-project registry and safety layer for Claude Code and Codex. It manages workspace identity, project paths and registered branches, agent directory permissions, built-in agent instructions, and workspace validation.

Starting with 2.0.0, this project is a focused multi-project management tool. It no longer provides extensions, an extension registry, an extension runtime, or monitoring. Workspace Guard, the add-projects skill, and the branch-resolution skill ship as built-in CLI assets.

## Requirements

- Node.js 20.19.0 or newer
- Each registered project is a Git repository

## Installation

```bash
npm install -g code-workspace-zhuiyi@2.0.0
```

## Initialize

Interactive:

```bash
codew init .code-workspace
```

Non-interactive:

```bash
codew init . \
  --tools claude,codex \
  --language en-US \
  --yes
```

`--tools` accepts `claude`, `codex`, `none`, or a comma-separated combination. Development mode controls dependency installation in the Code Workspace source checkout; ordinary workspaces can use `--dev false`.

Initialization writes only Workspace-owned state and integrations:

- `.codew/config.yaml`
- `.codew/config-projects.yaml`
- `.codew/state.json`
- `USER_GUIDE.md`
- `CLAUDE.md` and/or `AGENTS.md`
- Workspace-specific agent skills and commands
- Claude / Codex project-directory authorization

It does not create `openspec/`, install extensions, create monitoring hooks, or execute extension entry points.

## Register projects

Project paths must come from explicit user input. Inspect first:

```bash
codew project inspect /absolute/path/to/project --json
```

Claude Code users can explicitly invoke:

```text
/codew:add-projects /absolute/path/to/project
```

Codex users can invoke:

```text
$codew-add-projects /absolute/path/to/project
```

Automation can provide complete records over stdin:

```bash
cat projects.json | codew project add --stdin --yes --json
```

The registry stores each project name, canonical location, registered branch, type, and context:

```yaml
# .codew/config-projects.yaml
schemaVersion: 1
projects:
  - name: payments
    location: /absolute/path/to/payments
    branch: main
    type: backend
    context: |-
      Service responsibility and concise AI navigation context.
    updateLatest: true
```

`.codew/config.yaml` references this file through `projects.ref`. The referenced file must be a safe ordinary filename in the same `.codew` directory. Agents must not edit it directly.

## Daily commands

```bash
codew project list --json
codew project show payments --json
codew project verify payments --json

codew project branch inspect payments --json
codew project branch verify payments --json
codew project branch use-registered payments --yes --json
codew project branch accept-actual payments --yes --json
codew project branch update-latest payments --json

codew permissions apply --yes --json
codew doctor --json
```

The registered branch is Workspace desired state; the actual branch is an observed Git worktree fact. The user chooses the reconciliation direction:

- `use-registered`: switch back to the registered branch;
- `accept-actual`: update the registry to accept the actual branch;
- resolve manually, then run `verify`.

`updateLatest` only fetches and fast-forwards explicitly enabled, branch-aligned, clean worktrees. Workspace does not create or download branches and does not stash, reset, rebase, non-fast-forward merge, edit production code, or resolve conflicts.

## Agent authorization

```bash
codew permissions apply --yes --json
```

The command shows the complete authorization plan, then grants only missing authorization for registered project directories and verifies the result. It does not revoke extra directories.

## Update and language

```bash
codew update --json
codew update --language en-US --json
codew language --json
```

Updates manage Workspace-owned assets only. Unknown local changes fail before writing; use `--force` only after reviewing and intentionally overwriting them.

## Migrating from 1.x

Version 2.0.0 removes the experimental extension platform, including:

- `extension *`
- `ext`
- `config *`
- Nexus Registry and local Extension Store
- the monitor extension and Codex monitoring hooks
- extension packaging, development, and runtime protocols

`init` and `update` continue to recognize `.codew/ext-manifest.json`. Doctor reports legacy extension state; safely identified ordinary-extension files and extension hooks are removed by the confirmed `update --yes` cleanup plan. Locally modified legacy files are preserved and reported for manual review.

Built-in Workspace Guard takes ownership of the files formerly generated by the `codew-workspace-guard` system extension. Local modifications require explicit review before overwrite.
