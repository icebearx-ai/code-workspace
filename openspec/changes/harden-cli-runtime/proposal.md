## Why

CLI 是初始化、更新、项目管理和 Agent Skill 的执行边界，但当前手写的参数解析、全量配置校验、临时拼接的兼容逻辑以及不完整的回滚语义，会让无关缺陷破坏所有下游工作流。在继续增加命令和配置字段之前，需要先为 CLI 建立一致的运行时契约。

## What Changes

- 引入声明式命令注册表，使参数和选项具备命令语义，并拒绝未知或多余输入。
- 将配置文档解析与领域投影分离，使命令只校验自身实际消费的配置。
- 为受支持的旧配置建立具备版本感知能力的只读兼容机制，并在维护性写入时显式迁移。
- 为写命令引入统一的计划效果生命周期，明确区分可回滚的工作区变更和可验证的外部效果。
- 统一命令结果、诊断信息、退出行为和机器可读的 JSON 契约。
- 增加契约矩阵，覆盖参数顺序、旧配置、事务失败注入以及面向 Skill 的 CLI 用法。

## Capabilities

### New Capabilities

- `cli-runtime`：定义语义化命令解析、按依赖范围执行命令、稳定结果以及计划式写入行为。

### Modified Capabilities

- `workspace-language-configuration`：允许与工作区语言无关的命令操作受支持的旧配置，同时在真正需要或持久化语言的场景中保留严格校验。

## Impact

- 影响 `src/cli.js`、配置加载、初始化/更新编排、错误渲染、补全生成和 CLI 测试。
- 现有的项目、校验、Monitor 和受管文件等核心业务逻辑，仍可在新的运行时边界后复用。
- Skill 模板和 README 示例继续作为 CLI 契约的消费者，并增加自动兼容性检查。
- 不改变工作区文件布局，也不改变 OpenSpec 工作流。
