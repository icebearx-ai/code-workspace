## 背景

当前 CLI 将解析、路由、配置校验、交互、变更和渲染集中在同一个模块中。核心业务模块已经具备原子写入、受管文件规划、项目校验和 Doctor 诊断等有效保护，但调用方之间没有统一的运行时协议。因此，一个新增的必填字段或选项，可能会意外阻断无关命令和 Agent Skill。

本设计必须保留现有命令名称、工作区布局、受管资产和 OpenSpec 集成，同时让 CLI 边界变得明确且可测试。

## 目标 / 非目标

**目标：**

- 使命令语法声明化，并且不依赖参数顺序。
- 只加载和校验命令所需的配置域。
- 只读访问受支持的旧配置时不产生隐式写入，并在显式维护操作中完成迁移。
- 为写命令提供统一的检查、规划、应用、验证事务边界。
- 将文本、JSON、诊断、退出码、文档和 Skill 视为同一命令契约的消费者。

**非目标：**

- 重写现有的项目、校验、Monitor 或受管文件领域逻辑。
- 引入插件系统、数据库或新的工作区文件布局。
- 假定全局包安装或第三方命令能够原子回滚。

## 设计决策

### 声明式命令注册表与语义解析器

命令注册表定义命令路径、位置参数、类型化选项、工作区要求、配置依赖、交互模式和效果分类。语义解析器先解析命令，再消费其选项；拒绝未知或多余输入，并生成统一的调用对象。Help 和命令补全的命令列表均从注册表派生。

之所以选择这一方案，而不是继续扩展现有通用解析器，是因为缺少命令上下文时无法正确推断选项元数。成熟的参数解析库仍可作为实现选择，但注册表才是架构契约，从而避免将行为耦合到特定框架。

### 配置文档与领域投影

配置访问拆分为宽容的文档读取器，以及工作区身份、语言、Monitor 设置和项目等显式投影。命令只请求自己声明的投影。持久化配置之前以及严格健康检查中，仍必须执行完整校验。

读取器识别配置 Schema 版本，并保留“字段缺失”和“字段非法”的区别。兼容适配器可以在读取时派生旧值，但只有 init/update 可以持久化迁移后的文档。

### 版本化兼容策略

明确当前配置版本和最低可读版本，并使用旧配置夹具定义受支持的读取行为。与缺失旧字段无关的命令仍可使用；依赖该字段的命令返回带修复建议的稳定诊断。遇到未知的未来 Schema 版本时直接失败，且不重写文档。

### 计划效果生命周期

写命令遵循检查、规划、确认、应用、验证和提交的生命周期。工作区文件效果使用统一快照和补偿机制，并跟踪新建文件和目录。外部效果在工作区提交前执行并验证，同时明确报告其不可回滚属性。

首批迁移目标是 init、update 和项目变更，因为它们构成了面向 Skill 的关键写入链路。

### 稳定的命令结果

处理器返回结果或结构化诊断，而不是在领域逻辑深处选择输出格式。渲染器统一负责文本/JSON 输出和退出状态。迁移可以渐进进行，但新的命令契约和错误路径必须使用稳定错误码。

所有机器可读结果使用同一个信封：`schemaVersion`、`ok`、`command`、`data` 和 `diagnostics`。文本输出从同一结果对象派生。`--json` 同时表示非交互执行；需要确认的写命令若没有 `--yes`，必须在应用任何效果前返回稳定的确认错误。

### 配置 v2 与迁移注册表

当前配置版本提升为 v2。缺少 `schemaVersion` 的文档识别为 v0，现有 `schemaVersion: 1` 文档识别为 v1。纯函数迁移注册表负责生成从 v0/v1 到 v2 的迁移计划；只读投影可以兼容读取旧域，但只有 init/update 可以提交迁移。未来版本继续拒绝读取和重写。

### 工具选择的唯一事实来源

所有命令通过同一个解析器确定工具集合，优先级固定为显式 `--tools`、持久化 state、manifest 默认值。解析结果同时包含来源，并且显式工具变更只有在工作区事务成功后才写入 state。Doctor、update、init 和受管文件安装不得各自推导工具集合。

### Doctor 的逐域诊断

Doctor 使用宽容文档读取和 identity、language、monitor、projects 独立投影。单个域失败不得清空其他有效域；依赖无效域的检查应报告跳过原因，而不是使用虚构的空配置制造次生诊断。

### 可审计的效果报告

文件事务报告精确的 restored、removed、retained 和 rollbackFailures，而不是笼统承诺整个工作区已回滚。外部命令必须有命令专属后置验证。无法补偿的全局安装、依赖目录或第三方生成物作为 retained effect 明确保留在失败诊断中。

## 风险 / 权衡

- **大范围路由调整可能导致现有命令回归** → 保留既有领域函数，在兼容性测试保护下迁移命令边界，不重写业务行为。
- **领域投影可能让不健康配置长期存在** → Doctor 和所有配置写入继续执行完整校验；投影只隔离无关读取。
- **事务描述可能夸大外部回滚能力** → 效果计划单独分类外部操作，并在失败时报告仍然保留的外部变更。
- **注册表与文档可能发生漂移** → 从注册表生成 Help/补全，并在契约测试中校验 Skill/README 的命令示例。

## 迁移计划

1. 在保留现有处理器的同时，引入注册表、语义解析器、结构化错误和解析器契约测试。
2. 引入配置投影和旧配置夹具，将每个命令迁移到其声明的依赖上。
3. 提取统一的文件事务原语，并应用到 init、update 和项目变更中。
4. 为 JSON 输出和 Skill 增加消费者契约测试，然后移除过时的通用解析和重复快照逻辑。

每一步都保持公开命令名称稳定。若需回退，只回退运行时边界，既有领域模块保持不变。

## 待确认问题

没有阻塞问题。只要满足注册表契约和测试要求，是否选择第三方参数解析库可以继续作为实现细节。
