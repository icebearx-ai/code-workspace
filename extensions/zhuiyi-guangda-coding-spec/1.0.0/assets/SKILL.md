# 中国光大银行研发规范

## 使用边界

- 仅在项目、用户或仓库上下文已明确指向中国光大银行客户项目时使用本技能。
- 如果客户归属不清楚，先确认项目归属；不要仅凭技术栈或当前工作区名称套用本规范。
- 本技能补充客户研发要求，不替代用户需求、项目级 `AGENTS.md` 或更严格的合规要求。发生冲突时停止并说明冲突，不自行降低要求。
- 本技能用于开发、代码审查、测试与投产准备，不代替 DBA、安全、运维、业务或管理人员的正式审批。

## 最低执行基线

所有命中本技能的任务都必须做到：

- 从需求、现有代码和数据约束中确认行为，不擅自补写业务规则。
- 敏感校验和权限判断放在可信的服务端，不信任客户端传入的身份、权限、金额或关键业务字段。
- 处理空值、非法值、超长值、边界值、重复请求、超时和未明状态；异常路径不得静默吞掉。
- 数据库写入、删除、迁移和批量操作必须具备可恢复性；禁止用不可回滚操作换取短期实现便利。
- 外部输入进入 SQL、命令、模板、文件系统或响应输出前，使用对应上下文的安全机制。
- 不打印或返回密码、密钥、令牌、完整账号、内部地址、堆栈、SQL 等敏感信息。
- 只在需求范围内修改代码；不得夹带故障修复、数据修复或非必要维护性功能。
- 不声称执行过未实际执行的测试、审批、恢复演练或生产验证；无法由代码证明的事项明确标为待人工确认。

## 工作流

1. 明确客户归属、任务阶段、变更范围和涉及的数据/权限边界。
2. 根据“渐进式加载”表识别风险域；只读取相关参考文件。
3. 在设计和实现前把适用规范转成可验证约束，优先复用项目已有的安全、幂等、重试和回滚机制。
4. 实现或审查时逐项检查正常路径、异常路径、重复执行、并发执行、回滚和恢复。
5. 完成前使用 `references/process-checkpoints.md` 中与当前阶段相关的检查项做一次证据核对。
6. 最终说明已落实的规范、对应代码或测试证据，以及仍需 DBA、安全、运维、业务或管理人员确认的事项。

## 规范冲突

规范与现有代码、需求或用户指令不一致时：

1. 引用冲突双方的具体要求。
2. 说明不同选择对正确性、安全、投产和验收的影响。
3. 让用户决定适用口径；在决定前不实现依赖该口径的逻辑。

当前规则整理自《双十红线规范》和《研发过程关键环节关注点》（2025 年 12 月）。若涉及需要逐字复制的命令、字段、配置或正式制度条款，应向用户索取正式原文或审批版本核对。
